# 《红黄绿》文字版 MVP

纯文字、单机可玩的推理对抗游戏实现。1 个真人 + 机器人填座，或全机器人观战。

配套文档：
- `../红黄绿-MVP规则文档.md`（v0.2，第 11 章为文字表现层）
- `../红黄绿-文本资源清单.md`（130 条文案，本实现取材于此）

---

## 跑起来

```bash
cd mvp
node src/cli.js            # 单机：8 人局，你 + 7 个机器人
node src/cli.js 6          # 6 人局
node src/cli.js 8 12345    # 指定人数与随机种子（可复现）

npm run net                # 联机：起服务器，浏览器打开 http://127.0.0.1:8787
npm run net -- 9000        # 换端口
npm run net -- 9000 10     # 端口 9000，每房 10 人

node src/watch.js 8 3001   # 观战：全机器人打一局，按时间线输出
node src/sim.js 20 8       # 批量对局统计（20 局 8 人）
node test/balance.js 10    # 平衡矩阵：6~10 人 × 1~2 凶手
node test/run.js           # 规则回归（16 项）
node test/net.test.js      # 联机 + 聊天端到端（21 项，自带服务器）
```

无第三方依赖，Node ≥ 18 即可。

## 联机怎么玩

1. 房主 `npm run net`，浏览器打开 `http://127.0.0.1:8787`；
2. 名字留空房间号 → **加入/新建**，会拿到房间号（如 `R001`）；
3. 其他人填同一个房间号加入（局域网用 `http://<房主IP>:8787`）；
4. 房主点 **开局**：不足 6 人自动补机器人，最多 10 人；
5. 每个人只看到自己该看到的信息——别人的线索、身份、目标不会出现在你的界面。

**聊天频道**（规则 1.1 / 11.1 / 11.6 的落地）

| 频道 | 谁能看到 | 开放条件 |
| --- | --- | --- |
| 区域 | 同一区域节点内的玩家 | 始终 |
| 公开会 | 全场 | 仅公开阶段 |
| 阵营 | 仅凶手 | 凶手始终可用 |
| 幽灵 | 仅已被淘汰者 | 淘汰后 |

限制：单条 ≤ **60 字**、**2 秒**冷却、10 秒内超 **5 条**会被折叠——这三条是防刷屏下限，也是"文字游戏必须能读"的保证。

技术上用 **HTTP + SSE**（服务端推送），不是 WebSocket：零依赖、断线自动重连、可以直接用 `fetch` 测试。房间里的一次对局是一个 async 循环，轮到真人时挂起等 `POST /api/answer`，机器人同步应答。

## 与规则文档的差异（MVP 取舍与平衡补丁）

这些是有意的实现选择，不是遗漏。**改动都会影响手感，建议按此版本先测，再回头改规则文档。**

### 结构差异

| # | 差异 | 原因 |
| --- | --- | --- |
| D1 | **回合制时间**：一个动作推进虚拟秒数（搜索 3s、处决 3s、开会 90s），不是实时 | 文字单机没有实时输入，回合制才能保证可读 |
| D2 | 距离全部改为**节点**（13 个），"同区域"= 同节点 | 见规则文档 11.2 |
| D3 | **没有语音、没有私聊**：只有四个文字频道 | 语音会破坏文字形态的可读性；私聊会让"谁跟谁说了什么"无法追溯 |
| D4 | 攻击前摇、处决/救援打断**未实现**（即时结算） | 回合制下打断需要反应窗口，成本高；用"警察惩罚 + 通缉值"补偿 |
| D5 | 抗辩名额默认 **1 人**（公开者信誉 < 50 时 2 人） | "验证期 10/20 秒"在回合制里无法表达，改为"能挤进几个人" |
| D6 | 被捕期间不可被攻击、通缉清零、第 4 次被捕出局 | 按附录 C 定案实现 |
| D7 | 联机用 **SSE 长连接**，不用 WebSocket | 零依赖、断线自动重连、可用 fetch 测试；代价是客户端→服务端无推送通道 |
| D8 | 没有断线重连恢复（重连后从头等下一次提示） | MVP 取舍；引擎状态在服务端，补一个 `resync` 推送即可 |

### 平衡补丁（实测后必须加的，否则对局不收敛）

| # | 补丁 | 不加会怎样 |
| --- | --- | --- |
| P1 | **致命度 3 的红线索穿透绿色保护** | 保护每轮可续，红标永远打不进去，全员僵持到 90 分钟 |
| P2 | 每轮每人只能用 **1 条绿线索**（抗辩或保护二选一） | 同一人可连续抗辩两次，指控命中率过低 |
| P3 | **黄线索指向有 60% 概率复用已有指向** | 两条黄线索几乎凑不出"同目标异区域"，黄升红形同虚设 |
| P4 | 60 分钟收束：**不再采信反证**、保底改为红线索、每 5 分钟自动开会 | 残局没有新证据，双方都推不动 |
| P5 | 6–7 人单凶手局：凶手 **+1 弹药 +1 绿线索** | 1v5 时凶手胜率 ~10% |
| P6 | 警察阶段没人被通缉时只走 10 秒（不是 40 秒） | 空转时间占掉整局 1/4 |

## 实测平衡（每档 10 局，`node test/balance.js 10`）

| 人数 | 凶手 | 侦探 / 凶手 / 平 | 平均轮 | 平均时长 | 平均淘汰 |
| --- | --- | --- | --- | --- | --- |
| 6 | 1 | 9 / 1 / 0 | 10 | 22 分 | 3.1 |
| 6 | 2 | 3 / 7 / 0 | 12 | 29 分 | 4.7 |
| 7 | 1 | 10 / 0 / 0 | 11 | 29 分 | 3.5 |
| 7 | 2 | 3 / 7 / 0 | 23 | 56 分 | 5.9 |
| **8** | **2** | **5 / 4 / 1** | **17** | **50 分** | **5.7** |
| **9** | **2** | **5 / 4 / 1** | **19** | **49 分** | **6.5** |
| 10 | 2 | 9 / 1 / 0 | 15 | 39 分 | 6.5 |

**结论：8–9 人 2 凶手是唯一接近 50/50 的配置**（目前默认值）。其余配置偏斜明显：6–7 人单凶手是凶手地狱，10 人 2 凶手是侦探碾压——这与规则文档 C-06 的预判一致，说明"红标阈值 3"在小人数下对凶手不利、在大人数下对侦探有利。

## 结构

```
mvp/
├── src/
│   ├── data.js      数值与文案（改平衡只改这里）
│   ├── engine.js    状态机：行动、战斗、公开会、警察、淘汰、结算
│   ├── ai.js        机器人：探索决策 + 公开会应答
│   ├── commands.js  指令解析 + 按钮式行动建议（CLI 与网页共用）
│   ├── chat.js      聊天频道、可见性、冷却与折叠
│   ├── view.js      视角渲染（状态行、线索卡、结算页）
│   ├── cli.js       单机客户端
│   ├── watch.js     观战模式
│   ├── sim.js       批量对局
│   ├── debug.js     单局全事件 dump（排查用）
│   └── net/
│       ├── server.js   HTTP 路由 + SSE + 房间注册（可被测试 import）
│       ├── room.js     房间循环：等真人操作、推送事件、提示超时
│       └── ui.html     浏览器客户端（纯文本界面，无构建）
├── test/run.js      规则回归（16 项，无依赖）
├── test/net.test.js 联机 + 聊天端到端（21 项，进程内起服务器）
├── test/balance.js  平衡矩阵
└── test/debug-draw.js  找平局局看残局
```

**引擎要点**

- 单一状态树 `state`，所有随机走 `state.rng`（`mulberry32`，种子可复现）。
- 事件日志带**可见性范围**（global / node / near / private），每个玩家只 `drain` 自己该看到的——这就是文字版的"视野"。聊天直接复用这套范围，所以"区域频道只有同节点能收到"不需要额外鉴权代码。
- 交互统一抽象成 `ctx.ask(player, spec)`：机器人同步应答、命令行阻塞读、联机模式挂起等 `POST /api/answer`。**同一套引擎因此能同时跑单机、观战、批量模拟和联机**。

## 联机层的实现取舍

| 决定 | 理由 |
| --- | --- |
| SSE 而不是 WebSocket | 零依赖；浏览器 `EventSource` 自带重连；Node 里用 `fetch` 就能做端到端测试 |
| 一房一 async 循环 | 引擎是顺序回合制，天然不需要并发调度；轮到谁就 await 谁 |
| 提示超时兜底（行动 60s / 会议 25s） | 有人掉线时不至于卡死整局，超时自动选保守选项 |
| token 随玩家发放 | 防冒名；局域网内够用，公网需要再加 HTTPS 与更严格的会话 |
| 事件按连接状态暂存 | 没连着的玩家不推进 `lastSeen`，重连后仍能补到未读事件 |


## 已知限制 / 下一步

1. **没有断线恢复**：掉线后重连不会回到原来的待回应提示，只能等下一个回合；引擎状态在服务端，补一个 `resync` 推送 + 重放未读事件即可。
2. **没有公网安全**：token 走明文 HTTP，只适合局域网；公网需要 HTTPS + 房间密码。
3. **机器人不会谈判**：认不出"我们三个人一起指他"这种协作，只用线索与仇恨投票，所以胜率不代表真人胜率。
4. **10 人局侦探过强**：可以考虑 10 人局凶手 +1 弹药，或给第二个凶手额外伪造成本减免。
5. **反诉、自首、报警** 已实现但机器人很少用，真人局的强度待验证。
6. **聊天没有历史回放**：刷新页面只看到新事件；时间线回放（11.8）还没做。
